# 行为特征分析与事件溯源平台

面向用户行为打点采集、事件参数规范、会话重放、热力图分析、特征工程提取与行为标签体系管理的本地化数据分析应用平台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `behavior-event-trace-hub:entries` 这一项，或调用 `resetModule(模块)`。

### 异常标签待复核清单（行动标签 ↔ 异常检测联动）

行动标签（标签规则命中）与异常检测（检测器结果）两个业务面在「标签异常联动」入口共用同一份
跨模块数据流，归并规则集中在 `frontend/src/api/review-merge.ts`（纯函数，可在 Node 下直接验证），
页面读写走 `frontend/src/api/review-service.ts`：

- **一份待复核项**：同一异常对象只生成一条待复核记录、只公开一个待复核结论。两个规则/两端同时
  命中同一异常行为时归并到同一条，标签规则与检测器两个来源都保留在 `命中来源` 证据里。
- **归属冲突**：同一业务端对同一异常对象再来一单，不另立项，请求收到归属冲突说明，检测证据并入
  既有项并标记 `conflicted`。
- **重复提交**：同一请求编号（`requestCode`）第二次提交整单拒绝，复核清单只写入一次；归并是
  幂等的，重复执行「重新归并生成清单」不会产生重复行。
- **两端联查**：异常复核清单与异常检测详情都从新生成的同一份待复核清单取数（`findHitBySource`），
  分析人员可在两端核对同一命中。
- **版本冲突仲裁边界**：同一份清单支持两种排法——按规则生效时间排列（复核清单）或按异常检测时间
  排列（异常来源清单），共同边界是每个异常对象只有一个对外结论。
- 原始命中请求池持久化在 `behavior-event-trace-hub:review-evidence`，与模块数据分键存储。
- `ACTI-0003` 与 `ANOM-0003` 在示例数据中命中同一异常对象 `ABO-0001`，清单只有一条并保留两个来源。
